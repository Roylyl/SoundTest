日期：2026-09-22；App版本：1.0.0。本次在桌面SoundTest原工程中增量集成，保留四个事件模型与原有三个Tab，没有创建新App，没有加入网络、摄像头或位置识别。

使用CPJKU DCASE 2025 Task 1简化CP-Mobile。推理仓库固定提交da99d532999c8148cf3e0c7e0f9782324c04071e，训练参考固定提交87a5f8c4957b00055f83f6f69af8c52b1a3bb405。
源checkpoint SHA256：399908d314b99e86b95c96edeea69de42710f23a7a0a53b2161931ed5f2425c8。
入口get_model_for_device(baseline, 'unknown')返回base_model；只导出这一通用分支，不使用a/b/c/s1/s2/s3的设备专用网络。训练参考仓库用于核对模型和设备适配方式，本轮没有重新训练。
选ONNX是为了复用现有ONNX Runtime 1.28.2的iOS/模拟器二进制。增加轻量ASCBridge C++接口，保持模型执行位于原串行AnalysisRunner；不新增另一套录音或日志。ONNX为CPU执行，不宣称使用ANE或Core ML。
## 输入与前处理

|项目|设置|
|---|---|
|波形|32 kHz、单声道、Float32，固定32000样本|
|STFT|n_fft 4096，win_length 3072，hop_length 500，周期Hann，center=true，reflect补边|
|Mel|256维，HTK，f_min=0，f_max=Nyquist，norm=None，功率谱|
|对数|自然对数log(mel+1e-5)，保留官方Float16特征舍入|
|网络|官方半精度权重转Float32计算；不是INT8模型|
|输出|10类logits，App计算softmax；类别顺序来自官方class_order|

STFT/Mel/log随ONNX图导出，避免Swift手写另一套频谱前处理。麦克风由AVAudioConverter直接生成32 kHz单声道；导入文件从原始解码结果分别生成事件16 kHz和场景32 kHz缓存，不从事件缓存上采样。模型预测接口只接收波形，不接收文件名、用例编号、人工标签。
支持类别：airport、bus、metro、metro_station、park、public_square、shopping_mall、street_pedestrian、street_traffic、tram。中文逐一对应机场、公交车内、地铁车厢、地铁站、公园、公共广场、商场、步行街、交通街道、有轨电车内。居家、办公室不在标签中。
## 转换一致性
先执行源Baseline的preprocess及通用base_model，再用同一份32 kHz PCM执行ONNX。参考文件为官方dummy.wav；另用已有ESC-50猫叫测试片段的前三秒检查非平凡输入。共4个一秒窗口，参考实现与ONNX的Top-1均一致；10类softmax最大绝对分数差0.0018466711044311523。
官方网络半精度与ONNX Float32不是逐位一致；测到的差异包括计算精度及前处理舍入影响。完整logits、误差、类别和工具版本保存在conversion-parity.json。这4窗只证明当前样例上的转换一致性，不能证明真实场景准确率，也没有把猫叫素材当作场景真值。
iOS模拟器通过同一份asc-reference.f32输入真实打包模型，10类分数与Python ONNX参考逐类比较，容差0.0001，测试通过。另测试44.1 kHz文件经Apple解码/重采样到32 kHz后的时长与样本数；未宣称Apple与torchaudio重采样逐位一致。
## 连续分析与日志
固定1秒窗，步长0.5或1秒；默认1秒。平滑默认平均最近3窗、连续2次候选相同，最低分0.40、前两名差值0.10。最早第4个完整窗口后确认；不足显示判断中，分数不足显示不确定。所有阈值为未校准测试起点，不能可靠检测未知场景。尾部不足1秒保留补零后的原始分数，但不参与确认。
每窗scene字段保存rawScores、smoothedScores、state、label、decisionAudioTime、averagingStart/End/Count；记录options.scene保存设置，taskType区分任务。相邻窗口state/label改变的位置构成界面场景时间线，完整窗口数据随JSON分享。时间线为判定时的音频位置，不是人工标注的环境切换边界。
沿用inferenceMS等原有计时字段，模型调用、排队、窗口等待与UI交付分别记录；真实声源起点延迟没有独立测量，留空。声音事件仍保留原有多标签与事件合并逻辑，不使用场景softmax替代。

## 复现
转换环境：Python 3.12，torch 2.8.0、torchaudio 2.8.0、torchvision 0.23.0、numpy 2.5.3、onnx 1.23.0、onnxruntime 1.30.0、soundfile。iOS运行库仍为项目现有ONNX Runtime 1.28.2。
将推理仓库克隆到Research/dcase2025_task1_inference，并checkout上述固定提交，保留原目录与checkpoint；准备项目原有测试素材后执行Scripts/export-asc.py，再执行Scripts/prepare-manifest.py。Research目录为本地研究缓存，已忽略；App只打包转换后的通用模型和类别表，不打包源checkpoint及设备模型。不要对不可信checkpoint执行pickle加载。

```sh
python Scripts/export-asc.py
python Scripts/prepare-manifest.py
xcodebuild -project SoundTest.xcodeproj -scheme SoundTest -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project SoundTest.xcodeproj -scheme SoundTest -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -parallel-testing-enabled NO test
```

当时 ASC 接入新增必要资源 2,369,927 字节，彼时五组模型合计 50,170,190 字节；这是历史阶段的校验值。现已新增 M05 EfficientAT，当前六组模型必要资源合计 69,966,128 字节，以根目录 `ModelsManifest.json` 为准。模型/标签分别校验 SHA256。训练源码与源 checkpoint 未进入 App，YAMNet 特征加自训练场景分类器未接入。
