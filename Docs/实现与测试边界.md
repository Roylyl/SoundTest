# SoundTest 实现与测试边界
版本：1.0.0。本文将当前实现与《SoundTest_声音识别测试记录.md》的 S01–S17 对齐，区分已经具备的测试能力和需要采样验证的声音效果。实际 iPhone 成绩由测试人填写，构建、单元测试或模拟器推理通过不能替代现场记录。
## 1. 当前实现
SoundTest 是独立 iOS 工程，保留原 ASRtest。可切换的声音事件模型为 Zipformer-small Audio Tagging INT8、CED-Tiny INT8、CED-Mini INT8、YAMNet 和 EfficientAT mn10_as；必要权重与配套标签随应用准备，加载前核对文件大小与 SHA256，每次只保留当前模型实例。
|层次|文件 / 接口|负责内容|
|---|---|---|
|采集与文件|`AudioCapture`、`AudioFileIO`、`MonoAudioResampler`|后台音频会话、实际路由、状态化重采样、单声道 PCM、本地文件解码与用户主动保存片段。|
|统一模型调用|`TaggingEngine.classify(samples:sampleRate:)`|仅接收音频样本和采样率，返回原始标签、各自模型索引和分数；不接收文件名、测试编号或人工标签。|
|模型适配|`SherpaTagger`、`YAMNetTagger`、`EfficientATTagger`|sherpa 与 EfficientAT 各返回全部 527 类，YAMNet 返回全部 521 类；各模型分别执行其配套前处理。|
|分窗与事件|`WindowPlanner`、`EventAnalysis`|规划音频位置、标记尾窗补零、独立类别阈值、同类事件合并及估计范围。|
|调度与日志|`AnalysisRunner`、`SoundController`、`SoundSessionStore`|串行加载与推理、采集积压检查、计时、UI 更新、本地 JSON 保存和历史记录。|

底部三个原生 Tab 分别为测试、日志及模型信息、设置。测试页可录音或导入音频、选择 S01–S17、查看中文名 / 原标签 / Top-5、重点目标分数、逐窗结果和事件时间线。设置页切换模型与输入、调整适用窗口 / 步长 / 阈值 / 合并间隔；模型使用中锁定配置。日志支持查看、删除和用户发起的 JSON 分享。
## 2. 声音事件口径
当前只对四个业务目标发出提示：猫狗叫声、咳嗽、笑声和鼓掌。猫狗叫声聚合 Bark、Yip、Howl、Bow-wow、Growling、Whimper (dog)、Purr、Meow、Hiss、Caterwaul；咳嗽使用 Cough；笑声聚合 Laughter、Baby laughter、Giggle、Snicker、Belly laugh、Chuckle, chortle；鼓掌聚合 Clapping、Applause。每个业务目标取组内最高原始分数，不求和；日志保留实际胜出的原标签和全量分数。Animal、Domestic animals, pets、Dog、Cat 等父类只作观察项，不能单独触发猫狗叫声。
Top-5 只截取展示，原始窗口仍保存全部类别。重点目标不在 Top-5 时继续读取原分数；不存在或没有返回的类别以空值显示，不填成零。各类别独立判断，允许同时出现；默认 0.30 是未校准的观察起点，不是通用正确标准。分数不是准确率、事件概率校准结果或误报率。
目前这些模型本质上执行音频片段分类。连续监听由 App 分窗反复调用，不是模型原生输出精确起止的 SED 系统。当前事件范围按阳性窗口中心前后各半个步长估计，并按同类间隔合并；同时保存真正参与分析的证据窗口范围。显示估计范围的目的，是便于观察先后和重叠，不据此声称精确定位到真实声音起点。
## 3. 单段、连续与尾窗
单段模式在停止录音后按配置窗口分析，首页汇总各窗口平均分；短暂事件可能被平均稀释，应展开逐窗结果。连续模式边收音边处理完整窗口；不使用只放行人声的 VAD，也不因文件名或人工注释跳过预测。
sherpa 默认窗口 10 秒、步长 2 秒，设置范围内支持 1–30 秒窗口。YAMNet 当前文件输入固定 15,600 个 16 kHz 样本，即 0.975 秒，默认步长 0.48 秒；不能把它改成任意波形长度。EfficientAT mn10_as 使用 32 kHz 单声道、固定 10 秒窗口，默认步长 2 秒。三条前处理路径保持各自差异，不能仅因统一 PCM 就认定前处理相同。
文件与麦克风采用同一位置规划。到达精确完整窗口末尾时不重复生成尾窗；仍有未覆盖末尾音频时，仅补一个最后的不完整窗口，步长小于窗口时它会与前窗重叠。补零长度与实际音频范围分别记录，零样本不延长素材时长，也不作为真实事件证据。
当前前台单段录音上限 60 秒、连续采集上限 30 分钟、单次导入上限 10 分钟。麦克风 PCM 默认不落盘；本轮不超过 60 秒时可主动保存本地片段，更长的可复现素材采用直接导入。连续采集音频缓冲按窗口推进释放；推理待处理采样超过 30 秒时停止并报告过载，不静默丢窗。系统中断、输入路由变化或进入后台时结束当轮并留痕，需要用户重新开始。
## 4. 计时与记录解释
|字段 / 项目|含义|不能替代的指标|
|---|---|---|
|加载与校验耗时|校验必要文件并创建模型实例的耗时|首次结果耗时、每窗推理耗时。|
|`inferenceMS`|一次模型 `classify` 调用耗时，整轮值为各窗之和|等待收音、排队或界面展示时间。|
|`windowCollectionSeconds`|实际有效窗口覆盖的音频时长|相邻重叠窗口之间额外等待的时长。|
|`additionalAudioWaitMS`|上一窗处理结束后，等待本窗新音频的估计时长；已积压时为零|原始声源起点到检测到的真实延迟。|
|`queueDelayMS`|按采集时钟估计的窗口就绪到推理开始间隔|单独模型性能。|
|`promptAfterWindowMS`|有效窗尾到发布 UI 状态的间隔，含排队、推理与 UI 等待|精确屏幕呈现或真实事件起点到提示的延迟。|
|`trueEventLatencyMS`|真实事件起点不可得时保留空值|不能用分类窗开始时间补造测量值。|
|`stopWaitMS`|用户停止后到分析结束的等待|正常连续窗口延迟。|

采集时钟以录音 gate 开启时刻近似锚定，仍包含未单独测定的硬件、系统缓冲与转换误差。文件输入时间线取素材音频位置，收音等待与实时提示延迟留空。实时窗口的最终展示时间在当轮日志确认，不能用模拟器的输出耗时代表 iPhone 表现。
每次记录模型与文件版本、设备和实际路由、输入方式、素材身份与注释、窗口设置、全部原始分数、事件提示、耗时及异常。直接导入、扬声器回放录音、现场采集分组比较。JSON 中每个原始分数以 `[类别索引, 原始标签, 分数]` 保存；属于紧凑编码，不是删掉标签或只留 Top-5。
## 5. S01–S17 与当前 App 对照
|编号|在当前 App 中怎样测|需要人工确认 / 真机补测|
|---|---|---|
|S01 猫叫|导入或采集多段真实猫叫，展开猫狗叫声的胜出原标签和窗口。|是否触发组合业务目标；猫叫单独统计，开发单例不是完整成绩。|
|S02 狗叫|导入或采集多段真实狗叫，与猫叫使用相同业务阈值。|是否触发组合业务目标；不同犬类发声形态的覆盖。|
|S03 咳嗽|导入获准咳嗽录音，查看 Cough 和混淆标签。|不同人、强弱和次数；不能据此判断健康状态。|
|S04 笑声|覆盖成人、儿童、单人、多人和不同强度的真实笑声。|Laughter 等组内原始标签、命中和漏检。|
|S05 鼓掌|覆盖单次拍手、连续拍手和多人掌声。|Clapping、Applause 均按正类，不互记为错类。|
|S06 静音与普通无目标|分别导入数字静音、普通背景、讲话、音乐、电视或风扇。|四个业务目标误提示次数；不能要求全部原始分数为零。|
|S07 猫狗易混淆声|逐个测其他动物、宠物非叫声和人的动物拟声。|错误猫狗叫声提示及宽泛父类影响。|
|S08 咳嗽易混淆声|逐个测清嗓、喷嚏、吸鼻、喘息和吞咽。|错误咳嗽提示。|
|S09 笑声易混淆声|逐个测讲话、哭声、尖叫和喘气。|错误笑声提示。|
|S10 鼓掌易混淆声|逐个测敲门、敲桌、拍物、关门、脚步、碰撞和弹指。|错误鼓掌提示。|
|S11 目标叠加背景|为同一阳性素材制作固定背景混合版并保留配方。|与干净版本相比的漏检、误报与分数变化。|
|S12 不同目标先后出现|导入带独立人工时间标注的五种内容序列。|顺序、拖尾、跨类错报和错误合并。|
|S13 两个目标同时出现|导入重叠与各自单独出现的对照文件。|两类是否同时保留；区分模型漏检与阈值过滤。|
|S14 短声、窗边界与文件尾|按当前窗口与步长移动同一短声，另测文件开头和末尾。|补零、重复提示、漏检和估计范围。|
|S15 同类连续与间隔|两次同类声音采用小于、等于和大于合并阈值的间隔。|事件数与合并规则是否一致。|
|S16 长时无目标运行|听审确认无目标后前台连续监听10分钟起步。|按有效负样本时长计算FA/h，记录积压、卡顿和热状态。|
|S17 长时背景插入目标|在长时背景中插入带标注目标。|阳性区间命中/漏检；剔除阳性区间后统计误报。|

App 的用例选择仅提供记录归属，不播放预设答案，不自动判定“通过”。S01–S05 需分别准备独立阳性样例；顺序、重叠、误报和时间范围评测需另备有明确来源与人工标注的素材。断网冷启动、重复启停、权限/中断和日志/资源验证作为 A01–A04 应用检查单独记录，不按模型重复。
## 6. 已有证据与后续项
`Tests/Unit/AnalysisTests.swift` 对类别缺失、阈值、多类别、边界与合并规则进行语义测试。三组 sherpa 的真实模拟器推理及原始输出记录在 `SherpaIntegration.md`、`SherpaSmokeResults.txt`；YAMNet 的本地模型结构和模拟器推理记录在 `YAMNet接入说明.md`。EfficientAT mn10_as 的 iOS 前处理与 PyTorch 参考值核对，以及五组各 100 份 WAV 的模拟器批测结果，见 `验证结果.md` 第五节。完整工程的最新编译、测试与真机待测状态以根目录 README 和测试输出为准；程序运行通过不等于声音识别准确性得到验证。
`Tests/Unit/Fixtures` 提供猫叫、狗叫、咳嗽、笑声和鼓掌各一段 ESC-50 功能检查素材，所属测试目标与许可见该目录 README。其判定关注解码、分窗和全部分数能否正确返回，不以每个预期类别必须超过阈值作为程序测试通过条件；单例命中也不能当作正式 S01–S05 样本集或准确率。
EfficientAT `mn10_as` 已作为 M05 本地接入，使用固定版本权重导出的 ONNX、配套 527 类标签及独立前处理；目前完成模拟器文件输入和数值核对，尚未完成物理 iPhone 的麦克风、耗时、内存及温升验证。`mn04_as` 仍属于另一个待评估配置。仓库：https://github.com/fschmid56/EfficientAT 。
Apple Sound Analysis 可后续作为独立系统对照，并标明不是开源权重；PANNs DecisionLevel 仅保留电脑端时间定位参照。
