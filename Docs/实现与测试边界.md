# SoundTest 实现与测试边界
版本：1.0.0。本文将当前实现与《SoundTest_声音识别测试记录.md》的 S01–S17 对齐，区分已经具备的测试能力和需要采样验证的声音效果。实际 iPhone 成绩由测试人填写，构建、单元测试或模拟器推理通过不能替代现场记录。
## 1. 当前实现
SoundTest 是独立 iOS 工程，保留原 ASRtest。四组模型为 Zipformer-small Audio Tagging INT8、CED-Tiny INT8、CED-Mini INT8 和 YAMNet；全部必要权重与配套标签随应用准备，加载前核对文件大小与 SHA256，每次只保留当前模型实例。
|层次|文件 / 接口|负责内容|
|---|---|---|
|采集与文件|`AudioCapture`、`AudioFileIO`、`MonoAudioResampler`|后台音频会话、实际路由、状态化重采样、单声道 PCM、本地文件解码与用户主动保存片段。|
|统一模型调用|`TaggingEngine.classify(samples:sampleRate:)`|仅接收音频样本和采样率，返回原始标签、各自模型索引和分数；不接收文件名、测试编号或人工标签。|
|模型适配|`SherpaTagger`、`YAMNetTagger`|sherpa 返回全部 527 类，YAMNet 返回全部 521 类；前处理由各自配套运行库 / 原模型图执行。|
|分窗与事件|`WindowPlanner`、`EventAnalysis`|规划音频位置、标记尾窗补零、独立类别阈值、同类事件合并及估计范围。|
|调度与日志|`AnalysisRunner`、`SoundController`、`SoundSessionStore`|串行加载与推理、采集积压检查、计时、UI 更新、本地 JSON 保存和历史记录。|

底部三个原生 Tab 分别为测试、日志及模型信息、设置。测试页可录音或导入音频、选择 S01–S17、查看中文名 / 原标签 / Top-5、重点目标分数、逐窗结果和事件时间线。设置页切换模型与输入、调整适用窗口 / 步长 / 阈值 / 合并间隔；模型使用中锁定配置。日志支持查看、删除和用户发起的 JSON 分享。
## 2. 声音事件口径
首批重点类别为 Knock、Bark、Cough、Vehicle horn, car horn, honking；在每个模型自己的标签表中按原始名称匹配。Dog 等父类照常保留分数，但不自动代替 Bark 命中。中文“敲击（含敲门）”不等于“确认访客敲门”。扩展类别开关用于门铃、警报、流水、婴儿哭和通用冲击声；冲击提示不输出“确认有人跌倒”。
Top-5 只截取展示，原始窗口仍保存全部类别。重点目标不在 Top-5 时继续读取原分数；不存在或没有返回的类别以空值显示，不填成零。各类别独立判断，允许同时出现；默认 0.30 是未校准的观察起点，不是通用正确标准。分数不是准确率、事件概率校准结果或误报率。
所有首批模型本质上执行音频片段分类。连续监听由 App 分窗反复调用，不是模型原生输出精确起止的 SED 系统。当前事件范围按阳性窗口中心前后各半个步长估计，并按同类间隔合并；同时保存真正参与分析的证据窗口范围。显示估计范围的目的，是便于观察先后和重叠，不据此声称精确定位到敲击或咳嗽起点。
## 3. 单段、连续与尾窗
单段模式在停止录音后按配置窗口分析，首页汇总各窗口平均分；短暂事件可能被平均稀释，应展开逐窗结果。连续模式边收音边处理完整窗口；不使用只放行人声的 VAD，也不因文件名或人工注释跳过预测。
sherpa 默认窗口 10 秒、步长 2 秒，设置范围内支持 1–30 秒窗口。YAMNet 当前文件输入固定 15,600 个 16 kHz 样本，即 0.975 秒，默认步长 0.48 秒；不能把它改成任意波形长度。两种前处理路径保持各自差异，不能仅因统一 PCM 就认定前处理相同。
文件与麦克风采用同一位置规划。到达精确完整窗口末尾时不重复生成尾窗；仍有未覆盖末尾音频时，仅补一个最后的不完整窗口，步长小于窗口时它会与前窗重叠。补零长度与实际音频范围分别记录，零样本不延长素材时长，也不作为真实事件证据。
当前前台单段录音上限 60 秒、连续采集上限 30 分钟、单次导入上限 10 分钟。麦克风 PCM 默认不落盘；本轮不超过 60 秒时可主动保存本地片段，更长的可复现素材采用直接导入。连续采集音频缓冲按窗口推进释放；推理待处理采样超过 30 秒时停止并报告过载，不静默丢窗。系统中断、输入路由变化或进入后台时结束当轮并留痕，需要用户重新开始。
## 4. 计时与记录解释
|字段 / 项目|含义|不能替代的指标|
|---|---|---|
|加载与校验耗时|校验必要文件并创建模型实例的耗时|首次结果耗时、每窗推理耗时。|
|`inferenceMS`|一次模型 `classify` 调用耗时，整轮值为各窗之和|等待收音、排队或界面展示时间。|
|`windowCollectionSeconds`|实际有效窗口覆盖的音频时长|相邻重叠窗口之间额外等待的时长。|
|`additionalAudioWaitMS`|上一窗处理结束后，等待本窗新音频的估计时长；已积压时为零|原始声源起点到检测到的真实延迟。|
|`queueDelayMS`|按采集时钟估计的窗口就绪到推理开始间隔|单独模型性能。|
|`promptAfterWindowMS`|有效窗尾到发布 UI 状态的间隔，含排队、推理与 UI 等待|精确屏幕呈现或真实事件起点到提示的延迟。|
|`trueEventLatencyMS`|真实事件起点不可得时保留空值|不能用分类窗开始时间补造测量值。|
|`stopWaitMS`|用户停止后到分析结束的等待|正常连续窗口延迟。|

采集时钟以录音 gate 开启时刻近似锚定，仍包含未单独测定的硬件、系统缓冲与转换误差。文件输入时间线取素材音频位置，收音等待与实时提示延迟留空。实时窗口的最终展示时间在当轮日志确认，不能用模拟器的输出耗时代表 iPhone 表现。
每次记录模型与文件版本、设备和实际路由、输入方式、素材身份与注释、窗口设置、全部原始分数、事件提示、耗时及异常。直接导入、扬声器回放录音、现场采集分组比较。JSON 中每个原始分数以 `[类别索引, 原始标签, 分数]` 保存；属于紧凑编码，不是删掉标签或只留 Top-5。
## 5. S01–S17 与当前 App 对照
|编号|在当前 App 中怎样测|需要人工确认 / 真机补测|
|---|---|---|
|S01 敲门|选 S01、导入或现场录一组敲击，展开 Knock 分数和窗口。|开头是否漏检，敲门与敲桌声学标签和业务含义分开判断。|
|S02 狗叫|同一获准狗叫文件依次切换四模型，查看 Bark 及父类排名。|不同真实狗叫样例、回放链路和背景下的漏检；开发狗叫样例不是完整成绩。|
|S03 咳嗽|导入获准咳嗽录音，查看 Cough 和混淆标签。|与清嗓、喷嚏、笑声的区分，不能据此判断健康状态。|
|S04 汽车喇叭|使用同一文件重测，单独保留喇叭原始分数。|警笛、汽笛、发动机混淆与不同环境差异。|
|S05 背景噪声|记录相同目标的干净 / 固定混合版本，或固定风扇背景录音。|目标分数与误提示变化；没有声学校准时不填写 SNR 数值。|
|S06 无目标 / 静音|分别导入数字静音、普通背景、讲话或音乐，查看重点目标提示。|非目标输出是否符合音频，四类目标误提示次数。不能要求所有分数为零。|
|S07 离线冷启动 / 切换|断网后重启，依次载入四组内置模型并分析同一音频。|iPhone 首次安装后的离线行为、加载耗时及内存。|
|S08 重复启停 / 切换|同模型三轮录音，再 A→B→A；上一轮完成后切换。|尾部、权限准备取消、连续重复操作，以及是否混入上一轮结果。|
|S09 易混淆声音|同一套背景和反例逐个导入，保留原标签和目标分数。|区分声学类别相似与业务误提示，冲击不能算确认跌倒。|
|S10 距离 / 朝向|固定声源、输入和播放音量，分别记录实际距离与朝向。|必须使用真实采集 / 回放链路，直接导入不能完成此项。|
|S11 先后顺序|导入带独立人工时间标注的固定序列，观察逐窗和事件时间线。|与真实发声范围逐项比较，估计窗口中心不是精确事件边界。|
|S12 多事件重叠|导入重叠与单独出现的对照文件，查看多个重点类别。|模型是否保留较弱目标；区分模型漏检与阈值过滤。|
|S13 短事件 / 边界|按当前模型窗口和步长移动同一短事件，另测短文件与文件末尾。|补零影响、重复提示和事件合并效果。完整窗不重复尾窗已有语义测试覆盖。|
|S14 同文件 / 格式|重用已导入素材切模型，另导入同源 16/48 kHz、单/双声道版本。|实际素材转换是否正确、时长和尾部；不同转换不要求逐位同分。|
|S15 连续稳定性|前台连续监听，先做 10 分钟，再视情况延至 30 分钟。|iPhone 发热、电量、实际处理覆盖、长时误报和积压；未用短推理声称全天可靠。|
|S16 权限 / 路由 / 中断|拒绝或恢复权限、连接与断开输入、切后台，再检查日志并重新开始。|实际麦克风设备、系统打断和恢复动作须真机确认；本版不承诺锁屏常驻。|
|S17 日志 / 资源 / 导出|查看并分享完整 JSON、删除记录后重启；开发副本模拟资源缺失 / 哈希不匹配。|导出的配置与当轮一致；坏记录不影响其余记录；异常不得写成内容识别成功。|

App 的用例选择仅提供记录归属，不播放预设答案，不自动判定“通过”。基础 S01–S08 仍需独立样例和人工记录；顺序、重叠和误报评测需要另备有明确来源与时间标注的素材。
## 6. 已有证据与后续项
`Tests/Unit/AnalysisTests.swift` 对类别缺失、阈值、多类别、边界与合并规则进行语义测试。三组 sherpa 的真实模拟器推理及原始输出记录在 `SherpaIntegration.md`、`SherpaSmokeResults.txt`；YAMNet 的本地模型结构和模拟器推理记录在 `YAMNet接入说明.md`。完整工程的最新编译、测试与真机待测状态以根目录 README 和测试输出为准，本文件不据这些工程检查给四个模型做准确性排名。
`Tests/Unit/Fixtures` 提供每个重点类别一段 ESC-50 功能检查素材，所属测试目标与许可见该目录 README。其判定关注解码、分窗和全部分数能否正确返回，不以每个预期类别必须超过阈值作为程序测试通过条件；单例命中也不能当作正式 S01–S04 样本集或准确率。
EfficientAT 优先评估 `mn04_as`，必要时再比较 `mn10_as`：固定权重与类别表，先完成电脑参考输出，再验证移动端转换、独立前处理与全量分数误差，最后加入 iPhone 测试。当前未接入，不在可用模型中展示。详细方案见 `YAMNet与EfficientAT后续评估.md`，仓库：https://github.com/fschmid56/EfficientAT 。
Apple Sound Analysis 可后续作为独立系统对照，并标明不是开源权重；PANNs DecisionLevel 仅保留电脑端时间定位参照。当前四组模型的交付不依赖这些后续项。
