# SoundTest 数据集与评测方案
版本：1.0.0；更新：2026-09-21。依据新版《声音识别研究报告》第一处“四、声音识别相关的数据集和学术比赛”及配图，并核对原始发布页、类别表和赛事规则。本文件区分资料调研、已完成的工程验证与待开展的正式评测。
## 一、本轮采用的方向
SoundTest 继续围绕敲门、狗叫、咳嗽、汽车喇叭，逐步回答“有没有、何时出现、能否同时出现、何时误报”。首批四模型仍是片段分类模型，App 通过分窗生成事件提示；这与模型原生输出事件时间的 SED 有区别。
先用少量独立片段检查声音内容与调用链，再用强时间标注和受控混合验证顺序、重叠及边界，最后在实际设备上检查背景误报和持续运行。公开数据、合成声景、扬声器回放、现场采集分别报告；不把模型公开榜单成绩换算为手机识别准确率。
## 二、数据集怎样使用

|资源与原始来源|标注与本项目相关性|安排和限制|
|---|---|---|
|ESC-50：https://github.com/karolpiczak/ESC-50 |2,000段5秒片段、50类，含 door_wood_knock、dog、coughing、car_horn；单片段类别标签。|首轮四类功能检查和混淆样例。没有事件起止；沿用原始声源分组/官方折。完整集含非商业条款，ESC-10许可不同，需同时核对所选文件。|
|AudioSet 弱标注：https://research.google.com/audioset/download.html |527类本体，四类目标有对应项；给出片段标签，不给出片段内部事件起止。|统一语义、查训练来源及选取片段；未列出的类别不能一概当作已确认不存在。发布的是标注与视频定位信息，不是可任意再分发的整套音频。|
|AudioSet Strong：https://research.google.com/audioset/download_strong.html |2021年强标注总体456类，含事件起止；已核对评估标注中四类目标均存在。|优先研究真实录音的时间与重叠测试。按可取得、许可适用且听审通过的音频建立子集，保留原始划分；不是声称完成456类官方评测。|
|FSD50K：https://zenodo.org/records/4060432 |51,197段、200类，片段多标签；评估集在其词表内做穷尽标注，仍没有事件起止。|补充声源多样性和易混淆声音。词表外声音可能存在；需逐文件核查许可，有些带非商业条款。不能把“穷尽片段标注”写成“时间强标注”。|
|UrbanSound / UrbanSound8K：https://urbansounddataset.weebly.com/urbansound.html 、https://urbansounddataset.weebly.com/urbansound8k.html |原始 UrbanSound 含长录音事件位置，但每份录音只针对一个类别标注；8K 是8,732段不超过4秒的10类切片，含 dog_bark、car_horn。|补充狗叫、喇叭、交通混淆。8K的 start/end 是在原录音中的切片位置，不能直接当切片内精确发声边界；其他未标类别也不能自动当负例。|
|DESED：https://github.com/turpaultn/DESED |家庭声音，混合弱标注、无标注、真实及合成强标注资源；2024基线十类含 Dog、Alarm_bell_ringing、Running_water 等。|用于狗类、铃声/报警、流水与家庭混杂。核心四类中只有 Dog 相关，且不等于狭义 Bark；不覆盖敲门、咳嗽、汽车喇叭的四类完整评测。使用哪一部分及其标注类型必须注明。|
|COUGHVID v3：https://zenodo.org/records/7024894 |众包咳嗽录音和元数据，不是现成的多类连续事件起止标注集。|补充咳嗽声源、录音设备及清嗓等混淆观察；筛选可用音频并听审。模型的咳嗽分数、数据中的咳嗽筛选分数与健康结论分别处理，不用于诊断。|
|MIVIA Audio / Road：https://mivia.unisa.it/datasets/audio-analysis/mivia-audio-events/ 、https://mivia.unisa.it/datasets/audio-analysis/mivia-road-audio-events-data-set/ |Audio 三类为玻璃破碎、枪声、尖叫；Road 为车祸碰撞和轮胎打滑。|扩展声、背景混合方法与交通混淆参考；车祸不是汽车喇叭。需注册获取，本轮未确认足以支持数据商用和再分发的明确许可，不内置其音频。|
|SAFE：https://www.kaggle.com/datasets/antonygarciag/fall-audio-detection-dataset |950段3秒声音，假人跌落与非跌落各475段；片段二分类，不是真实老人跌倒强标注。|仅留作模拟冲击声与日常声音专题。当前发布页版本5，CC BY-NC-SA 4.0；不列为默认可商用素材。App仍显示撞击声标签，不映射成“确认有人跌倒”。|

“数据集未标这四类”不等于“整套音频均无四类声音”。作为负样本使用前，需要听审或对本项目目标补标。上述资源没有在本轮整包下载或打入 App；现有工程仅有4段 ESC-50 功能检查音频，位于 XCTest 测试资源，正常 App 不携带这些 WAV。
## 三、类别映射和时间标注
AudioSet 系列优先用语义 MID 对照，再核查原始标签。不同数据集和模型的整数类别索引互不通用。Strong 中的汽车喇叭名称多出 `, toot`，与当前模型显示名不同，但 MID 相同；只比较字符串会漏掉这一对应关系。

|目标|AudioSet MID|2021 Strong评估标注：事件行数 / 唯一片段数|
|---|---|---:|
|敲击 Knock|`/m/07r4wb8`|109 / 33|
|狗叫 Bark|`/m/05tny_`|547 / 161|
|咳嗽 Cough|`/m/01b_21`|375 / 151|
|汽车喇叭 Vehicle horn, car horn, honking, toot|`/m/0912c9`|297 / 145|

以上为直接读取固定版本官方 TSV 的覆盖核验，并非已下载音频数、独立声源数或模型测试成绩；多个类别可能属于同一片段，不能相加当作互不重复的样本总量。固定来源 URL、SHA256 与统计说明见 [AudioSet Strong核验记录](References/AudioSetStrong-2021-核验.json)。
参考答案保存在音频旁的独立表格/JSON中，至少包含 `sample_id、dataset/version、source_id、split、audio_sha256、原始标签/MID、annotation_type、onset/offset、来源许可、加工说明`；没有起止时留空。合成音频另外保存前景/背景原始编号、随机种子、增益、混合时间和最终听审标注。App 的素材编号、人工标签与来源字段只用于关联日志，不参与推理。
现有 App 可导入音频、记录人工参考文字和导出完整预测；尚未实现强标注文件解析、数据集批处理或自动 event F1/PSDS。时间参考当前由配套表格维护，正式评分需后续电脑端脚本。

Scaper 可在电脑上生成音频和独立注释，作为素材准备工具：https://github.com/justinsalamon/scaper 。插入片段的起止不自动等于片段内真实发声起止；先处理前后静音并听审成品。混合、SNR或位移变体不增加独立声源数量，也不能替代真实环境验证。

目前先记录固定配置下的具体漏检、背景误提示、重复提示和运行异常。形成独立测试集后，再按片段、事件和设备体验分别统计：
- 片段级：按事先固定的标签和分数聚合规则统计；不以跨模型分数大小排序，不把重叠窗口当独立音频。
- 事件级：使用独立起止真值，先固定类别映射、阈值、合并规则与匹配容差，再计算 precision/recall/F1；须注明测的是“模型＋分窗＋后处理”完整流程。
- 背景误报：合并后的错误目标提示数除以实际有效无目标录音小时数，另列事件内部的重复提示。短测零误报不推导长期可靠。
- 提示延迟：实际声源起点到UI首次提示需要独立测量；推理调用耗时、窗口等待、窗尾到UI提示继续分开。

PSDS需要多个阈值下的检测表现和强时间标注，不能由一次阈值的提示或Top-5直接得到。`sed_scores_eval` 要求分数区间连续、无重叠、无空隙；App的重叠窗口需经预先固定的时间投影/聚合规则转换，保留原始窗口证据。投影后的时间格子不代表模型原生帧级精度。工具与输入规范：https://github.com/fgnt/sed_scores_eval 。
## 六、数据独立性、使用条件与待研究项
划分以原始声源为单位；同一录音的裁切、重采样、增益、SNR混合和所有合成派生物放在同一侧。多个数据集可能共享 Freesound/YouTube 原始素材，应检查原始ID及音频指纹。阈值只在开发集选择，独立测试集固定后不再根据其结果调参。模型预训练来源可能与公开评测素材重叠，未核实排除前如实说明，不能宣称完全未见测试。
代码、模型权重、标注和音频各自核查许可；标签可获取不表示视频音频可以自由再分发。带非商业条款的数据不因“内部测试”就自动视为可商用；本轮不将这些专题数据整包内置。
新版资料中两处需要在后续报告引用时改正：SAFE 不应称“唯一公开跌倒声数据集”，其假人数据也不能代表真实人体跌倒；MIVIA 的混合实例数不能倒推为独立原始录音数，作者论文明确先分原始素材再复用混合，不能用 `6000÷6` 推出每类1000个独立声源。SAFE 当前许可核验：https://www.kaggle.com/api/v1/datasets/view/antonygarciag/fall-audio-detection-dataset ；MIVIA 原始论文第3节：https://www.cs.rug.nl/~nick/wp-content/uploads/2016/10/PRL-audio-bag-of-words.pdf 。
EfficientAT mn04_as 仍按原计划研究移动端转换。新增的电脑端原生帧级参考可看 PretrainedSED：https://github.com/fschmid56/PretrainedSED ，与已有 PANNs DecisionLevel 分别记录。其帧级输出、专属类别表和后处理值得对照，但当前没有完成 iOS 转换、因果流式、内存或耗时验证，不加入首批可切换模型，也不把输出时间维度当成真值。
