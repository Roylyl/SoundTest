## 二、公开单例输出的解释
测试采用 ESC-50 固定提交中的五段5秒、44.1kHz、单声道音频，分别对应猫叫、狗叫、咳嗽、笑声、鼓掌。每类按文件名排序预先选择第一段，未按模型分数挑选；来源、作者、许可、大小和 SHA-256 见 `../Tests/Unit/Fixtures/EnvironmentFixtures.json`。这些单例只检查真实音频解码、分窗、模型调用和业务聚合，不能代表准确率、召回率或 iPhone 麦克风效果。
以下数值是对应业务目标在该素材全部窗口中的最大原始分数。三个 sherpa 模型使用10秒窗，5秒素材显式补零；YAMNet使用0.975秒窗、0.48秒步长。窗口数量和补零条件不同，不能用本表直接做模型排名。
|模型|猫叫→猫狗|狗叫→猫狗|咳嗽|笑声|鼓掌|
|---|---:|---:|---:|---:|---:|

猫叫样例的胜出原始标签均为 Meow；狗叫样例依模型胜出为 Bark 或 Bow-wow；三套 sherpa 的笑声样例胜出为 Snicker，YAMNet 为 Laughter；鼓掌均为 Clapping。原始标签不同属于业务聚合预期行为，日志仍保留具体标签和全量分数。
默认阈值0.30下，Zipformer 的狗叫样例、CED-Tiny/CED-Mini 的咳嗽样例、YAMNet 的笑声样例不会产生业务提示。程序测试仍通过，因为它验证调用链和输出有效性，不以单例必须超过阈值冒充识别正确。四模型的数字静音均未触发四个业务目标；这不能推出真实背景下的长期误报结论。

## 五、EfficientAT mn10_as 增量验证（2026-09-23）
M05 使用本地 ONNX Runtime CPU 推理，输入为 32 kHz 单声道、固定 10 秒窗口，输出 527 类分数。iOS 前处理与官方 PyTorch 参考值使用同一段合成音频核对，128×1000 Mel 特征的最大绝对误差为 6.67572×10⁻⁶；同一音频的 527 类输出与参考值最大绝对差小于 10⁻⁶。模型权重、前处理资源及类别表的版本和校验值见 `../SoundTest/ModelsManifest.json`。
