# SoundTest

SoundTest 2.0.0 是本地运行的 iPhone、iPad 声音事件与环境场景测试工具，并提供配套 Apple Watch 声音事件测试 App。复用 ASRtest 的录音会话管理、输入源选择、资源校验、本地日志和原生界面处理。原 ASRtest 保持独立，SoundTest 不包含旧 ASR 权重。

## 打开与运行

打开 `SoundTest.xcodeproj`，选择共享 Scheme `SoundTest` 和自己的 iPhone 或 iPad 后运行。工程使用 iOS 17.0 最低版本、Swift 5；支持的系统使用原生 Liquid Glass 控件，低版本使用系统控件。当前使用 Xcode 27.1 构建；本地运行库支持 arm64 iPhone、iPad 和 Apple Silicon 模拟器。
在 Signing & Capabilities 中设置自己的开发团队和唯一 Bundle Identifier，并为 Watch App 配置相同团队。App 版本为 `2.0.0`，图标沿用蓝底白字两行文字：Sound / test。
需要在手表上测试时，先让 iPhone 与 Apple Watch 配对，在 Xcode 选择 `SoundTestWatch` Scheme 和该 Apple Watch 运行；Watch target 的 Bundle Identifier 是 iOS 标识后加 `.watchkitapp`，签名团队须与 iPhone App 一致。首次录音需在手表上授予麦克风权限。日志同步还需在配对 iPhone 安装并启动同一工程的 SoundTest。
模型和运行库已在本地工程准备好，Swift Package 仅引用 `Packages/SherpaTagging` 和 `Packages/YAMNetRuntime` 两个本地包。安装后可离线切换五组事件模型及一组场景模型，不需要下载或导入模型；完整断网冷启动与切换仍需在 iPhone 真机复核。
仓库使用 Git LFS 保存 `.onnx`、`.tflite`、Watch Core ML 权重、`.xcframework` 内二进制和测试 `.wav`。克隆后先确认已安装 Git LFS，并执行 `git lfs pull`；若只得到指针文件，Xcode 无法加载模型或链接本地运行库。

## 首批模型

下表仅列 iPhone/iPad 模型。大小是模型运行所需权重、类别表及前处理资源，按十进制 MB；不含许可文本，不等于安装大小和运行内存。六组共 **69,966,128 字节（69.97 MB）**。Watch 端的 Core ML YAMNet 权重另计，见 `Docs/AppleWatch集成与验证.md`。

|编号|模型|实际运行库|运行所需资源|输出与默认窗口|
|---|---|---|---:|---|
|M01|Zipformer-small Audio Tagging INT8，2024-04-15|sherpa-onnx 1.13.8 / ONNX Runtime 1.28.2|27.05 MB|527类；10秒 / 步长2秒|
|M02|CED-Tiny INT8，2024-04-19|同上|6.15 MB|527类；10秒 / 步长2秒|
|M03|CED-Mini INT8，2024-04-19|同上|10.47 MB|527类；10秒 / 步长2秒|
|M04|YAMNet，官方 iOS 示例配套 TFLite|TensorFlow Lite C 2.17.0|4.13 MB|521类；固定0.975秒 / 步长0.48秒|
|M05|EfficientAT `mn10_as`，由官方 PyTorch 权重转 ONNX|ONNX Runtime 1.28.2 CPU；本地 Accelerate 前处理|19.80 MB|527类；固定10秒 / 默认步长2秒|
|ASC01|DCASE 2025 CP-Mobile 简化版，通用 base_model|ONNX Runtime 1.28.2 CPU|2.37 MB|10种环境；固定1秒 / 默认步长1秒|

YAMNet 使用官方 MediaPipe iOS 示例引用的同一模型，直接通过本地 TensorFlow Lite C 运行，复用本 App 的录音和分窗调度。文件 URL 名称包含 `float32`，但嵌入元数据说明模型内部为8位量化；实际输入、输出均为 Float32。未复制 MediaPipe 的整套录音和图调度层。
三个 sherpa 模型使用各自同包的527类表；YAMNet 使用从所选 TFLite 内嵌资源提取的521类表。EfficientAT 使用其官方527类表，本地前处理生成128×1000的 Mel 输入；ONNX 图内已有 sigmoid，输出分数不再二次转换。中文显示映射版本 `soundtest-zh-v1`，按原始英文标签匹配，覆盖事件模型所有类别；日志始终保留原始标签与数值索引。声音事件模式只对猫狗叫声、咳嗽、笑声和鼓掌四个业务目标发出提示，其他原始类别用于调试和解释。M05 的转换、文件校验和数值核对见 `ModelLibrary/efficientAT/README.md`。
固定来源、版本、大小与 SHA256 在 `ModelsManifest.json`；运行库清单分别位于 `Docs/SherpaRuntimeFiles.json` 和 `Packages/YAMNetRuntime/RuntimeManifest.json`。运行时加载前校验每个必要文件，校验失败即报错。一次只保留当前模型实例。

在宽屏 iPad 上，测试页将控制区和识别结果分为左右两栏，分别滚动；窄屏 iPad 和 iPhone 使用单列。日志与设置页限制阅读宽度，仍保留原生列表、表单和导航行为。
输入源变化会自动刷新。录音中发生路由变化、系统中断或进入后台时结束当前会话并记录原因，避免把两个设备的采集混成一条结果；不承诺锁屏后台长期监听。修改模型、输入和识别参数须等待本轮完成。

## Apple Watch 配套 App

同一 Xcode 工程中的 `SoundTestWatch` target 是 watchOS 10 及以上的配套 App，图标沿用 SoundTest。界面为四个可左右滑动页面：选模型、实时结果、日志、设置。Watch 端有两条本地推理路径：Apple Sound Analysis 系统分类器，以及使用手表麦克风、Swift/Accelerate 声学前处理和 Core ML 权重的 YAMNet。两者都只把猫狗叫声、咳嗽、笑声和鼓掌作为业务目标；音频不经 iPhone 或服务器推理，默认不保存原始录音。Apple 系统模型不是开源权重；YAMNet Watch 版使用社区 Core ML 转换件，与 iPhone 使用的 Google TFLite 文件分开标记。
现有 iPhone 模型的 sherpa-onnx、ONNX Runtime 和 TensorFlow Lite C 二进制均没有 watchOS 切片。因此 Zipformer、CED-Tiny、CED-Mini、EfficientAT 和 CP-Mobile 在手表模型页明确不可选；YAMNet 通过另行数值核对的 Core ML 路径接入，而非复用 iOS TFLite 库。Watch 端仅在前台录音，系统中断或退到后台时结束该轮。Apple Sound Analysis 不提供独立的纯推理耗时，该字段留空；YAMNet 单独记录 Core ML 调用累计时间，不把采集等待计入。具体平台差异和验证范围见 `Docs/AppleWatch集成与验证.md`。
Watch 日志先写入手表本地 `Documents/WatchLogs`。在手表日志页点击“导出并同步至 iPhone”后，文件通过 WatchConnectivity 异步传输；iPhone 实际接收并存入独立的 `Documents/WatchLogs` 后回传确认。iPhone“日志及模型信息”页底部的“查看 Apple Watch 上的日志”用于查看和分享这些记录。传输排队不等于已送达，手表会分别显示排队、传输和 iPhone 已接收状态；配对真机上的送达、YAMNet 速度/内存和麦克风表现仍需实测。

## 使用步骤与默认设置

1. 在“设置”选择模型并等待就绪，核对实际输入源、窗口、步长和阈值。
2. 在“测试”选择单段识别或连续分窗，选择用例编号，填写素材编号与参考标签。
3. 文件测试点“单个音频”后分析；多文件测试点“批量 WAV”，多选文件后点“开始本轮测试”。录音测试选择真实环境或回放方式，点“开始录音”，结束后点“停止录音”。
4. 查看Top-5、重点类别、完整分数和时间线；等待本轮完成，再切换模型重测同一文件。
5. 在“日志及模型信息”查看或分享记录，将记录编号填入配套测试记录表。导出所有结果时，滑到页面底部点击“导出全部日志（ZIP）”，等待打包完成后通过系统分享面板保存到“文件”或发送。

默认CPU线程为2，四个业务目标阈值均为0.30，同类合并间隔为0秒；这些是测试起点，尚未校准。可点“恢复当前模型默认值”后核对设置。三个sherpa模型窗口可设1–30秒，步长选项为0.5、1、2、5、10秒且不能超过窗口；YAMNet窗口固定0.975秒，步长可选0.24、0.48、0.975秒；EfficientAT窗口固定10秒，步长可选2、5、10秒。
首轮默认使用同一台iPhone的内建麦克风，先导入同一份音频对比模型，再做回放和现场采集。M01–M03应固定窗口、步长、阈值和线程后比较；M04保留其固定短窗差异，M05保留32 kHz前处理差异。模型分数更高、窗口更多或时间线更密，都不能直接证明效果更好。

## 测试方式

- **单段识别**：录音结束后按当前窗口配置分析。事件模式显示各窗口平均分，场景模式保留逐窗原始/平滑预测；窗口结果仍逐窗保存；单段麦克风最长60秒。
- **连续分窗**：录音同时分窗处理，显示最近窗口结果，保存全部窗口与多类提示。默认前台运行，单轮最长30分钟；队列积压超过30秒会明确终止并记录异常，不静默跳窗。
- **直接导入**：支持系统可解码的 WAV、M4A 等音频，最多10分钟；导入后可切换模型反复分析。文件模式按音频位置生成时间线，不按电脑/手机计算快慢生成事件位置。
- **批量 WAV**：系统文件选择器可一次多选1–100份 WAV，每份最多10分钟，按文件名顺序逐个解码和分析。选择时临时复制文件到本机，分析时只保留当前文件的目标采样率数据；不会同时展开整批PCM。清空或替换列表会删除旧的临时副本；原始文件保持不变。列表只在当前App会话内保留，重启后需重新导入。一次执行固定当前模型和设置；切换模型后可对同一列表“再测一轮”，生成新的日志组。
- **复现片段**：麦克风原始音频默认只留内存，60秒以内的本轮录音可主动点击“保存测试片段”，写入本机 `Documents/Samples` 后分享。更长的复现测试优先使用直接导入。单文件导入不另存音频，批量导入使用上文所述的临时文件副本。
所有输入显式下混全部通道；M01–M04声音事件模型重采样至16 kHz，M05 EfficientAT及环境场景模型重采样至32 kHz单声道。文件导入从原文件分别生成两种采样率，场景输入不会从16 kHz缓存上采样；没有语音VAD，没有按人声过滤环境声，也没有按文件名或参考标签选择结果。文件名、样本编号、人工标签、来源与许可只写日志。直接导入、扬声器回放录音和真实环境采集分别记录。
批量测试以原始文件名作为素材标识；同名文件仍有独立条目，不按文件名推断类别或用例编号。为避免把单文件的参考答案误套到整批，批量记录的用例标为“批量文件”，人工标签留空。单个坏文件会记录失败原因并继续下一项；主动停止或进入后台时，保留已完成及当前文件已产生的结果，剩余文件标为“未运行”。日志保存失败会停止整轮。运行时保持App在前台。
YAMNet 每窗严格15,600样本（0.975秒）；sherpa 使用自身配套前处理，窗口可设1–30秒；EfficientAT 每窗为320,000样本（10秒），由本地 Accelerate 前处理。未满尾窗时显式补零，只在尚有未覆盖尾部时额外生成一次部分窗口；日志分别保留有效范围、实际模型输入时长和补零时长。

## 环境场景识别（ASC）

ASC回答整体环境类别，独立于事件标签，不根据喇叭、狗叫等事件推断环境。测试页选择“环境场景”，默认切换到CP-Mobile与连续分窗；也支持停止录音后分析及同一文件反复测试。一次只加载一个模型，沿用录音、校验、日志与三个原生Tab。
使用官方 `baseline.ckpt` 的通用 `base_model`，对应 `unknown` 设备分支；没有套用 a/b/c/s1/s2/s3 数据集设备分支。模型输入为1秒32 kHz单声道。STFT、256维HTK Mel与自然对数前处理随ONNX图一起导出，iOS只负责解码、下混与重采样。固定标签及中文显示如下：

|原始标签|中文显示|
|---|---|
|airport|机场|
|bus|公交车内|
|metro|地铁车厢|
|metro_station|地铁站|
|park|公园|
|public_square|公共广场|
|shopping_mall|商场|
|street_pedestrian|步行街|
|street_traffic|交通街道|
|tram|有轨电车内|

居家、办公室不在支持类别内。softmax分数是十个已知类别内的相对输出，不是准确率；高分不能证明输入属于已知环境。“不确定”只是低分或候选接近时的展示规则，不是可靠的未知场景检测器。
默认1秒窗/1秒步长，平均最近3窗，连续2窗候选一致且第一名≥0.40、领先第二名≥0.10才展示场景；最早在第4个完整窗口后得到确认。步长可选0.5或1秒，平均窗数和确认次数可调。积累不足或新候选尚未确认时显示“判断中”，分数不足时显示“不确定”。这些参数尚未经设备实测校准。尾部不足1秒会补零并保留原始分数，但不产生确认场景。
每窗分别记录10类原始分数、平滑分数、平滑覆盖范围、状态与判定音频时间；时间线由相邻状态/类别变化生成。时间为结果可用的音频位置，不是精确环境切换边界。原始预测不会被平滑结果覆盖。日志Schema升级为2，仍可读取原声音事件Schema 1记录。
模型与转换来源、复现步骤和验证结果见 `Docs/ASC/集成与验证.md`。新增人工记录为 `Docs/SoundTest 环境场景测试记录.md`，该文件位于本仓库。YAMNet特征加自定义场景分类器未接入，需要独立数据与训练后评估。

## 分数与事件提示

声音事件模式只对四个业务目标发出提示：猫狗叫声、咳嗽、笑声和鼓掌。每个目标独立使用自己的阈值，默认0.30仅为测试起点，尚未按真机素材校准。低于阈值时不提示；无目标输入不要求模型所有原始类别均为零。
|业务目标|纳入聚合的精确原始标签|
|---|---|
|猫狗叫声|Bark、Yip、Howl、Bow-wow、Growling、Whimper (dog)、Purr、Meow、Hiss、Caterwaul|
|咳嗽|Cough|
|笑声|Laughter、Baby laughter、Giggle、Snicker、Belly laugh、Chuckle, chortle|
|鼓掌|Clapping、Applause|
同一业务目标有多个原始标签时，App 取当前窗口中的最高分作为该目标分数，不求和；日志同时保留胜出的原始标签以及全部527或521类分数。`Animal`、`Domestic animals, pets`、`Dog`、`Cat` 等宽泛父类仍可在原始结果中查看，但不能单独触发“猫狗叫声”。猫叫和狗叫在测试记录中分别统计，以免只验证一侧后误称整个组合目标可用。
首页“模型原始 Top-5”只用于调试，业务提示只来自上表。重点目标未进入 Top-5 时仍会读取其原始分数；模型没有返回配置标签时显示缺失，不填成零。分数不等于识别准确率或校准概率。咳嗽提示不用于推断疾病；笑声不包含普通讲话、哭声或尖叫；鼓掌包含拍手和掌声，不包含敲门、拍桌、脚步或普通物体碰撞。扬声器回放目标声音被识别为相应目标，本身不算误报。
各类独立判断，可同时出现。每个提示保留两套时间：
- `evidenceStart/evidenceEnd`：触发提示的分析窗口联合覆盖范围。
- `estimatedStart/estimatedEnd`：阳性窗口中心前后各半个步长形成的估计范围，再按同类合并间隔连接。
时间线浅色表示窗口覆盖，深色表示估计事件范围。这是可复查的分窗提示规则，不是训练出的精确SED边界；短声、背景空隙、尾窗补零均可能影响范围。界面最多绘制最近40条事件、最近80个窗口；完整记录保留所有结果。

## 计时与日志

每次结束在 `Documents/Sessions/<UUID>.json` 保存完整日志，另存轻量 `.summary.json` 供历史列表使用。进入单条记录才读取全量分数，减少长测试对历史页内存的影响。损坏或不匹配的索引记录会跳过，详细记录损坏时明确提示。
批量测试另存 `Documents/Sessions/BatchGroups/<UUID>.json`，记录本轮名称、模型与设置、顺序、各文件状态及对应记录ID。每次点击“开始本轮测试”或“再测一轮”都会生成新的UUID；单条日志通过可选 `batch` 字段归组，旧Schema 1/2记录仍可读取。日志页优先显示日志组，进入后查看每份文件的完整结果；“成功”仅表示分析完成，不代表分类正确。整组分享导出一个含组信息和全部已保存记录的JSON，不包含音频。整组删除只删除本轮日志，不删除原音频或其他轮次。App异常退出后，下次启动会将未结束组标为中断，并保留可恢复的已保存结果。
单条或整组日志可左右滑动后点击删除，再确认；关闭全幅滑动自动删除，文件删除和日志重载在同一串行队列执行，列表一次性更新，避免滑动动画与异步刷新交错。日志页底部提供“清空日志”，确认后删除全部日志组、单条记录和生成的整组分享副本，保留模型、已保存测试音频和当前导入列表。测试、保存或删除进行中，删除与清空入口暂不可用。
底部“导出全部日志（ZIP）”会在后台生成当前日志的独立快照，包含全部完整记录 JSON 和 `BatchGroups` 日志组信息，保留组与记录的关联及全部原始分数；不重复打包轻量 `.summary.json`，不包含音频、模型和旧分享文件。没有摘要索引或暂时无法解析的原始 JSON 也会原样保留，避免遗漏排查材料。打包与日志保存、删除共用串行队列，打包期间暂停新的测试和删除操作；空库或文件读取失败会明确提示。每次导出使用独立文件，分享面板关闭后清理该次临时 ZIP，已保存或发送的副本不受影响。
日志记录模型文件和版本、设备、实际输入UID和采样格式、素材编号与文件SHA256、人工标签、窗口与步长、各类阈值、合并设置、中文映射版本、完整分数、事件、热状态、异常。`scores` 使用紧凑 JSON 三元组 `[类别索引, 原始标签, 分数]`，避免重复字段名造成长测文件膨胀。

|字段|口径|
|---|---|
|inferenceMS|只统计引擎classify调用；不含采集、重采样、UI和日志。|
|windowCollectionSeconds|有效窗口覆盖的音频时长，不能直接当作新增等待。|
|additionalAudioWaitMS|上次分析结束后等待本窗口新音频的估计时长；已积压时为0。|
|queueDelayMS|采集时间轴上的窗口就绪至推理开始。|
|promptAfterWindowMS|有效窗尾至UI提示，包含调用、排队与界面交付；不是从真实声源起点计算。|
|trueEventLatencyMS|当前没有独立物理起点测量，留空。|
|stopWaitMS|用户停止到尾窗分析结束；不含后续JSON写盘。|

麦克风计时基于App录音开启的单调时钟近似对齐音频位置，无法消除硬件缓冲延迟；实际声源提示延迟要由独立标注与真机测量补齐。文件模式的采集等待、队列等待、物理提示延迟均留空。

下表说明测试记录中S01–S17的操作。测试记录文件只填写当次配置、素材、结果和证据；应用介绍与使用说明统一维护在本README。

|编号与项目|操作参考|观察重点|
|---|---|---|
|S01 猫叫|分别使用多段真实猫叫；保留具体原始标签。|是否提示猫狗叫声；命中、漏检及错类。|
|S02 狗叫|分别使用多段真实狗叫，与猫叫独立统计。|是否提示猫狗叫声；不同叫声形态的覆盖。|

|S05 鼓掌|覆盖单次拍手、连续拍手和多人掌声。|Clapping、Applause 两种原始标签均按正类记录。|

|S09 笑声易混淆声|测普通讲话、哭声、尖叫和喘气。|错误的笑声提示。|
|S10 鼓掌易混淆声|测敲门、敲桌、拍物、关门、脚步、碰撞和弹指。|错误的鼓掌提示。|

|S12 不同目标先后出现|五种内容按人工标注顺序出现，中间保留背景。|顺序、拖尾、跨类错报和错误合并。|

|S17 长时背景插入目标|在长时背景中插入已知目标并独立标注阳性区间。|阳性区间命中/漏检；负区间误报、漏窗和稳定性。|

S01–S05测试声音本身，不是朗读类别名称。连续模式至少覆盖一个完整窗口。现场出现真实目标时必须补标，并从纯负样本时长中扣除。S16只统计听审确认无目标的有效时长；S17计算误报时只使用剔除已标注阳性区间后的负样本时长。
声音顺序、重叠、短声与边界素材应有独立参考标注；Scaper插入片段的范围不自动等于实际发声范围，需要处理静音并听审。素材来源、许可、原始ID、版本、哈希及加工方式均应保留。阈值在开发素材上选择，同源切片与混合派生物不跨开发/测试划分。
背景FA/h按合并后的错误业务目标提示数除以实际有效无目标录音小时数计算，合并规则固定，事件内重复提示另计。短测零误报不推导长期可靠。窗口范围、估计事件范围与人工起止真值分开；没有独立测量的物理提示延迟留空。滑窗重复处理音频，调用耗时除以原文件时长不能自动视为跨方案可比的单模型RTF。
应用功能另做一次构建级检查，不按每个模型重复：A01断网冷启动与六模型及任务切换；A02连续三轮启停及A→B→A切换；A03权限、后台、锁屏和路由中断；A04日志查看/分享/删除以及资源校验失败。详细结果填在配套测试记录的“应用功能检查”。

## 验证与后续

实际构建、模拟器自动化和样例推理证据见 `Docs/验证结果.md`。测试源码位于 `Tests/Unit` 与 `Tests/UITests`。可执行：
```sh
python3 Scripts/prepare-manifest.py
xcodebuild -project SoundTest.xcodeproj -scheme SoundTest -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project SoundTest.xcodeproj -scheme SoundTest -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -parallel-testing-enabled NO test
```
第一个脚本只验证已有来源清单并生成App清单，不下载模型，不将任意新文件的哈希自动认作可信来源。真机签名由Xcode处理。
配套人工测试记录在 `Docs/SoundTest_声音识别测试记录.md`；其中已有的 1.0.0 测试记录保留其原始版本信息，原事件测试文档保留既有内容，本轮另增场景记录；新版 S01–S17 口径记为 `soundtest-s01-s17-v2`。该文件记录当次配置、各事件模型结果、事件明细和对比结论。手机上的实际采集、持续运行、耗电与误报仍须实测；自动化成功和单个样例输出不能替代这些结论。
数据集和赛事的历史调研见 `Docs/数据集与评测方案.md`。其中早期四目标及 AudioSet Strong 统计属于改版前方案，不能作为当前猫狗叫声、咳嗽、笑声、鼓掌四目标已经覆盖的证据；当前没有整包内置这些数据集，也未实现 event F1 / PSDS 自动评分。
M05 EfficientAT `mn10_as` 已作为本地可切换模型接入；官方权重转换为固定10秒ONNX，iOS前处理与上游参考数据已做数值核对。独立 iPhone 18 Pro 模拟器将五类各 100 份 WAV 完成批测，500 条记录均成功保存；统一 0.30 阈值下来源目标命中 307/500，具体数据和边界见 `Docs/SoundTest_声音识别测试记录.md`。iPhone真机的内存、耗时、耗电及麦克风持续监听仍未核验。`mn04_as` 和 PANNs DecisionLevel 未接入；Apple Sound Analysis 仅接入配套 Watch App，iPhone 模型列表未接入。详见 `Docs/YAMNet与EfficientAT后续评估.md`。
